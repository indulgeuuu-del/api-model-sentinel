# 验证范围与兼容性

发行版应同时通过以下检查，具体运行结果见仓库Actions；此文档说明证据覆盖什么。

| 层次     | 验证内容                                                                         | 入口                                |
| -------- | -------------------------------------------------------------------------------- | ----------------------------------- |
| 核心     | 两种协议、JSON/SSE终态、错误/超时/取消、超预算正确答案、参数映射                 | `npm test`                          |
| 探针     | 64组小糖果袋独立穷举oracle、400组可复算变体、原题与JSON判定                      | `npm test`                          |
| 调度     | 并发、迟到响应、无积压补发、中断恢复、存储失败、比较预检、保护门禁               | `npm test`                          |
| HTTP     | 真实回环请求、认证、Host/Origin、跨站、SSE、请求体/响应体限制、脱敏导出          | `npm test`                          |
| 本机运行 | CLI真实子进程启停与重复实例拒绝、Windows DPAPI和启动器                           | `npm test`                          |
| 浏览器   | 桌面/手机布局、关闭页面后继续、费用/超时/答错、比较、编辑/删除、导出、键盘与锁定 | `npm run test:e2e`                  |
| 发布     | 语法/格式/敏感模式检查、仅白名单打包、ZIP与SHA-256                               | `npm run check` / `npm run package` |

测试不读取个人历史、不调用真实供应商、不使用旧Key，也不会停止正在工作的真实Codex会话。HTTP请求、SSE和CLI都是实际本机进程/网络验证；供应商语义与停止对象由可控夹具模拟。

## 显式真实供应商验收 · 2026-11-23

在用户授权的一个OpenAI兼容网关、模型ID `gpt-6-sol` 上执行10次请求：全部HTTP200，全部答案正确。供应商地址与原始请求ID仅保存在本机私有报告，不随项目发布；认证只用于请求，不写入报告。

| 协议      | 内容             | 请求推理强度 | 结果       | 报告总token |
| --------- | ---------------- | ------------ | ---------- | ----------: |
| Responses | 原糖果题         | none         | 21，通过   |        5484 |
| Responses | 简单整数兼容探针 | minimal      | 2，通过    |        4402 |
| Responses | JSON轮换题       | minimal      | 通过       |        4487 |
| Chat      | 简单整数兼容探针 | minimal      | 2，通过    |        4402 |
| Responses | 糖果变体         | none         | 16，通过   |        4862 |
| Responses | 运算与约束       | none         | 2150，通过 |        4448 |
| Responses | 最短路径         | none         | 16，通过   |        4533 |
| Responses | 表格筛选         | none         | 1465，通过 |        4532 |
| Responses | JSON轮换题       | none         | 通过       |        4487 |
| Chat      | 原糖果题         | none         | 21，通过   |        5656 |

每次请求输出预算均为16。报告总量合计47293 token，含供应商报告的39290缓存token；这是接口元数据，不是账单。网关多次将请求的none/minimal回传为medium，并在8次请求中报告输出超过16，原题两种协议分别报告869和1041输出token。软件保留正确通过并显示费用/参数提示，没有提高请求预算或自动重试。

这批结果验证所测网关当时的两种协议、原题、五维轮换和结果记录，不代表其他网关、其他模型、长期可用性或预算限制都已通过。常规测试不使用真实认证；需要复测时使用[显式真实验收工具](live-testing.md)，按已有报告挑选必要用例，避免重复消耗。

## 平台

GitHub CI矩阵：Windows、Ubuntu、macOS；Node22和24。Windows运行当前用户DPAPI验收，其他平台运行受限文件权限验收。Chromium桌面和移动尺寸的浏览器测试在Ubuntu执行，本机开发也可运行。

移动尺寸测试代表响应式浏览器交互，不代表手机可以访问电脑服务：HTTP只监听电脑本机回环地址。macOS/Linux的监测核心可用，Codex保护和空闲电源保持仅提供Windows实现。

## 真实环境已知限制

- 2026-11-23对Windows Codex Desktop `26.1117.4957` 做了只读能力检查：app-tools管道存在，但旧 `codex-ipc` 控制管道不存在，因此保护检查返回不可用。没有以真实工作做停止试验。
- Codex是非公开接口适配。模拟测试验证选择目标、并发去重、停止请求与结果确认；它不能替代某个桌面版本的实机验收。
- 未附带第三方供应商凭据。上述单网关实测不能覆盖其他路由；供应商支持哪些模型/推理参数、是否服从预算、是否准确上报用量，需要对自己的服务做“检测一次”。
- 关闭浏览器的后台调度已由真实浏览器与后台进程验证；主机睡眠恢复的时间语义通过时钟推进测试覆盖，不把它称为连续多夜实机耐久测试。
- 代码测试和CI不能证明100%无缺陷。已知未支持的能力在界面/文档中明确标记，新增发现进入带复现的回归测试。

## 手工验收建议

先演示正常、超时、费用告警与答错四个配置，再对自己供应商做一次原题请求。需要无人值守时保持主机唤醒，确认下次检测时间并关闭浏览器，之后重新打开查看记录时间和调度延迟。开启Codex保护前须通过能力检查；实机停止验证应使用专门的可丢弃测试会话，不应拿正在执行外部操作的工作会话试验。
