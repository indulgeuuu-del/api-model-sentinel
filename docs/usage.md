# 使用手册

## 启动、暂停、关闭

Windows双击根目录的 `Start.cmd`。第一次启动服务，之后重新打开同一个面板。服务会独立于网页运行；关闭Edge、最小化、锁屏或熄屏不影响调度。

“暂停监测”停止某个配置并取消当前本地等待。“暂停所有监测”停止所有配置，后台服务和面板仍可用。`Stop.cmd` 暂停所有配置并关闭服务。下次双击启动后，需要重新开启监测。

`Demo.cmd` 是独立演示。停止演示请在解压目录运行 `node bin/sentinel.cjs stop --demo`。演示里开启的保护仅模拟停止两个会话。

主机手动睡眠、休眠、关机期间无法发出检测请求。Windows的“防止空闲自动睡眠”只在监测开启期间申请电源保持，不阻止熄屏，也不修改系统电源计划。系统策略不允许保持唤醒时，面板会显示状态。macOS/Linux请自行保持主机唤醒。

## 填写配置

| 字段            | 用法                                                                                                          |
| --------------- | ------------------------------------------------------------------------------------------------------------- |
| API URL         | 支持基础地址和完整端点；空路径默认加 `/v1`。不使用 `/v1` 的供应商请填完整 `/responses` 或 `/chat/completions` |
| 协议            | Responses或Chat Completions，按供应商文档选择                                                                 |
| 模型名称        | 供应商实际接受的模型ID，界面不凭名称认证模型身份                                                              |
| API Key         | 密码框只负责写入。编辑留空保留旧Key，勾选“清除”才删除                                                         |
| 分组 / 版本标签 | 例如 `a-group-2026-11`。在供应商后台切换同Key分组时更新，避免混合统计                                         |
| 间隔            | 1–1440分钟，从上一次请求完成后计算；首次开启立即检测                                                          |
| 超时            | 5–300秒，到时取消本地等待，下一周期继续；供应商可能仍计费                                                     |
| 输出预算        | 16–32768 token；默认16，原题只答整数。JSON轮换题可能需要手动选择更大预算                                      |
| 推理强度        | 默认 `none`；不支持时可手动选择 `minimal` 或“供应商默认（不发送）”                                            |
| Chat token 参数 | 可按模型名选择或明确指定。请求失败不会自动再试另一种参数                                                      |
| Temperature     | 留空不发送，只在供应商支持时设置                                                                              |

先“检测一次”检查连通性和参数，再开启自动监测。修改前先暂停。参数、Key和标签变化后统计重新分组，历史记录仍保留。

## 运行规则

| 本次结果                   | 自动检测           | Codex保护                                            |
| -------------------------- | ------------------ | ---------------------------------------------------- |
| 正确，包括超预算正确       | 原间隔继续         | 不触发                                               |
| 有完整终答且答案错误       | 暂停该配置         | 仅在显式开启并通过能力检查后触发                     |
| 超时、503、429、网络错误   | 原间隔继续         | 不触发                                               |
| 拒答、未完成、无法解析答案 | 原间隔继续         | 不触发                                               |
| 用户暂停或取消             | 停止               | 不触发；迟到的远端答复也不触发                       |
| 本地磁盘保存失败           | 全部暂停并显示错误 | 不继续发送新请求；已确认的错误答案仍执行已授权的保护 |

服务重启时恢复已开启的计划。如果上次请求进行中发生崩溃，增加一条“中断，结果未知”，等待完整间隔再检测，不重发旧请求。主机时钟变化或睡眠恢复后只执行一次到期检测，不追补积压请求。

历史最多保留全局最近1000条，告警最多100条，达到上限后淘汰最旧记录。长期留档请定期导出JSON/CSV。已知token统计只累加供应商提供的用量，未知用量单独计数。

## Codex停止保护

此功能是Windows Desktop实验适配器。勾选后保存和开启前都会检查本机连接；无法连接时明确报错，不会宣称保护已开启。每次触发只针对快照中的本机活动会话，使用桌面停止动作，并再次检查停止结果；失败或状态不明会记录在告警中。

它不会删除会话、终止Codex进程、操作SSH远端聊天或CLI任务，也无法撤回已经完成的外部操作。桌面升级可能改变私有接口。当前检查过的 `26.1117.4957` 缺少旧IPC管道，因此目前该版本无法启用。请勿将未通过检查的保护作为无人值守工作的唯一保障。

## 导入、迁移和备份

面板“导出配置”不含Key。“导入配置”支持新版 `{profiles:[...]}` 和旧版 `{profile:{...}}` JSON，只导入配置，全部暂停且关闭Codex保护；Key需重新填写，除非导入源本身包含Key。应仅导入可信的本地文件，导入后检查URL与模型再启动。

旧版Windows后台配置可以显式迁移：先关闭新版服务，在新版目录运行：

```sh
node bin/sentinel.cjs migrate
```

它读取当前Windows用户的旧版 `CodexModelHealthGuard/scheduler.dpapi`，将配置导入新版加密存储；不修改旧数据，不启动监测，不迁移历史，也不会关闭旧服务。迁移成功后再启动新版并检查参数。需要另一目标目录时使用 `--data-dir PATH`。

备份前先停止服务，复制整个数据目录，包含 `state.enc`、`state.enc.previous` 及对应主密钥文件。Windows DPAPI备份受原系统用户保护，复制到另一台电脑未必能解密；跨电脑迁移优先使用不含Key的配置导出。恢复前保存原目录副本，不要单独混用不同目录的状态和密钥。

## 常见故障

| 现象                     | 处理                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------ |
| 关闭服务后网页打不开     | 双击Start.cmd；单独打开网页地址不会启动后台                                                |
| 没有连接码 / 401         | 双击Start.cmd或执行 `node bin/sentinel.cjs open`，用启动器打开带连接码的地址               |
| 端口占用                 | 不终止其他进程；用 `serve --port 17657 --open`，或调用start.ps1的Port参数                  |
| 供应商400 / 422          | 查看检测详情中的参数排查建议，按供应商文档手动调整                                         |
| 供应商503                | 对应接口或分组暂时不可用，监测继续；不判定为答错                                           |
| 仍生成推理token / 超预算 | 界面保留真实用量和提示；供应商可能忽略限制。按供应商支持选择none/minimal或更换分组         |
| 长时间没有记录           | 检查服务是否运行、主机是否睡眠、配置是否已因完整答错暂停，查看下次时间与记录里的调度延迟   |
| 磁盘失败 / 加密状态损坏  | 保留整个目录，先修复磁盘/权限，再在备份副本上恢复state.enc.previous；不要直接删除密钥      |
| 已有服务但状态异常       | 查看数据目录service-error.log；若实例锁损坏，先确认对应PID确实不在运行，再备份并处理锁文件 |

本机连接码能控制服务，API Key、完整数据目录和真实日志不应公开上传。问题反馈优先提供脱敏状态、协议、HTTP状态和可复现步骤。
